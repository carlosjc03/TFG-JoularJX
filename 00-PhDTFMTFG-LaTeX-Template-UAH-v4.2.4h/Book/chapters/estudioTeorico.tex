% Aquí es donde entra JoularJX, un agente Java de código abierto desarrollado por

% \cite{joularjx2022, joularjxrepo}. Un agente Java es un componente de software que la
% JVM carga dentro del mismo proceso que el programa que queremos medir, de modo que puede observar, medir o modificar lo que hace este en tiempo real sin necesidad de modificar su código fuente.
% JoularJX se conecta a la JVM al arrancar el programa y, en lugar de dar un único
% consumo total, calcula por separado cuánta energía gasta cada función del
% programa, de manera que podemos conocer cuáles son las que más consumen y así modificarlas para hacerlas más eficientes.
%

% ese momento, de forma que conoce el porcentaje del tiempo que ha estado activa
% cada una de ellas. En paralelo, cada segundo lee del procesador la energía consumida y
% calcula qué parte de esa energía corresponde al programa que se está midiendo.
% Después la reparte entre las funciones en esa misma proporción, lo que permite
% conocer una aproximación del consumo de cada una de ellas~\cite{joularjx3}.

\section{Introducción}
\label{sec:introduccion-teoria}


Este capítulo reúne la base teórica sobre la que se apoya este trabajo. La
revisión de lo que ya se ha investigado sobre el consumo energético del
software es importante porque permite partir de enfoques y herramientas que ya
han sido probados por otros investigadores, en lugar de empezar desde cero,
pero también porque ayuda a justificar por qué se ha elegido JoularJX y a interpretar correctamente sus mediciones.

El capítulo se divide en dos apartados. El primero presenta el estado del
arte, en el que se explica qué es el software sostenible, a qué niveles se
puede medir el consumo y qué herramientas existen para hacerlo. El segundo
profundiza en las técnicas y herramientas empleadas en este trabajo, como son
la medición de energía en el procesador, el funcionamiento interno de
JoularJX, las librerías Jackson y Gson y la herramienta JMH, con la que se
preparan las pruebas.

\subsection{El consumo energético del software}
\label{subsec:consumo-software}

En la introducción ya se presentó la ingeniería del software sostenible, o
\emph{green software}, como la disciplina que trata el consumo energético del
software como un criterio de calidad más ****a la hora de ****. El interés por este campo **por ello** no para de
crecer, ya que el sector de las tecnologías de la información consume una parte
importante de la electricidad mundial: solo los centros de datos suponen en
torno al 1,3\% del consumo eléctrico global, cifra que se acerca al 4\% si se
suman las redes de telecomunicaciones \cite{css2024it}. **algo de la huella de carbono***

Una de las ideas centrales del green software es que un mismo problema se puede
resolver de muchas formas distintas, y cada una gasta una cantidad de energía
diferente. Un buen ejemplo es la elección del lenguaje de programación. En un
estudio muy conocido, Pereira et al. compararon el consumo de 27 lenguajes
ejecutando las mismas tareas y encontraron diferencias enormes: tomando el
lenguaje C como referencia, Java gastaba alrededor del doble de energía,
mientras que Python llegaba a consumir unas 75 veces más \cite{pereira2017}. **tambien decir algo de la forma de programar como antes, epro tipo si hay algun estudio de recursivo vs iterativo sabes**
Esto demuestra que la tecnología elegida para construir un programa influye
directamente en lo que gasta.

Y no solo influye el lenguaje. Dentro de uno mismo, la forma de escribir el
código también cambia el consumo: las estructuras de datos que se usan, los
algoritmos o los patrones de diseño aplicados. De hecho, se ha comprobado que
algunos patrones de diseño muy habituales hacen que un programa gaste más o
menos energía según cómo se implementen \cite{noureddine2025}. Por eso, mejorar
el consumo de un software no depende de una única decisión, sino de muchas
elecciones tomadas a lo largo de su desarrollo.

Ahora bien, para saber qué decisiones son mejores desde el punto de vista
energético, antes hay que poder medir cuánta energía gasta realmente un
programa. En el siguiente apartado se explica a qué niveles puede hacerse esa
medición.
